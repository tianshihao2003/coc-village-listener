# 村庄JSON监听 —— 安卓应用设计文档

- 日期：2026-08-30
- 状态：待站长确认
- 目标设备：vivo X300 Pro（OriginOS，Android 15+ 底层）
- 交付物：APK 安装包（GitHub Release 下载）

## 1. 背景与目标

《部落冲突》国际服内置"更多设置 → 数据导出 → 以JSON格式导出村庄数据 → 复制"功能，复制后剪贴板里是一份村庄快照 JSON（含 `tag`、`buildings`、`traps`、`decos`、`helpers` 等字段，`data` 为游戏内部数据 ID）。站长的日常流程是：复制之后手动打开某个指定工具、粘贴 JSON。

目标：做一个**常驻后台的安卓应用**，检测到用户刚复制了这种格式的 JSON 时，自动拉起站长指定的软件，并把每份 JSON 自动存档，免除手动切换与整理。

## 2. 使用场景与验收标准

日常体验（配置完成后）：

1. 站长在游戏"更多设置"里点"复制"；
2. 3 秒内指定软件被自动拉起，JSON 仍留在剪贴板，切过去直接粘贴；
3. 通知栏弹一条"已捕获村庄数据 #TAG"；JSON 同时存入手机 `下载/村庄JSON/`。

验收标准：

- [ ] 游戏内点复制后，目标 app 自动打开，无需任何手动操作
- [ ] 每次复制都在 `下载/村庄JSON/` 留档，文件名 `#TAG_日期时间.json`
- [ ] 平时复制任何其他内容（微信文字、网址等）零干扰、不触发
- [ ] 同一份 JSON 重复触发时只动作一次
- [ ] 手机重启后 app 能明确提醒"Shizuku 未激活"并给出激活入口
- [ ] vivo X300 Pro 锁屏/后台一段时间后监听仍存活（配合保活指引）

## 3. 功能需求

### 3.1 剪贴板监听与识别

- 前台服务（通知栏常驻"村庄数据监听中"，低优先级、可折叠）承载监听。
- 通过 Shizuku（shell 级权限）读取系统剪贴板，轮询周期约 1.5 秒；监听到 `PrimaryClipChanged` 事件时立即读一次（事件 + 轮询双保险）。
- **识别规则**（全部满足才触发）：
  1. 内容 trim 后匹配正则 `^\{\s*"tag"\s*:\s*"#[0-9A-Z]+"`；
  2. `JSON.parse` 成功；
  3. 解析结果含 `buildings` 数组字段。
- **去重**：对内容取 SHA-256 前 16 位作为指纹，与最近一次触发指纹相同则不重复触发；中间复制过其他内容后再复制回同一份 JSON，视为新事件、正常触发。
- 解析失败或不符合特征的内容一律静默忽略。

### 3.2 触发动作

- 依次执行：
  1. 存档（见 3.3）；
  2. 发出"已捕获村庄数据 #TAG"通知，**点击通知可直接打开目标 app**；
  3. 自动拉起目标 app（`getLaunchIntentForPackage` + `FLAG_ACTIVITY_NEW_TASK`），剪贴板内容保持不动。
- 目标 app 未配置时：只存档 + 通知提示"请先在应用内选择要自动打开的软件"。

### 3.3 自动存档

- 通过 MediaStore 写入公共下载目录 `Download/村庄JSON/`（Android 10+ 应用自建文件无需存储权限）。
- 文件名：`#GJJ892V8P_2026-08-30_1530.json`（tag 从 JSON 读取，异常时用 `unknown`）。
- 存档开关可在应用内关闭；同一秒内重复触发以文件名加序号避免覆盖。

### 3.4 目标应用配置

- 应用内"选择软件"页：列出本机所有可启动应用（LAUNCHER intent 可解析），支持搜索，单选。
- 配置持久化到 SharedPreferences（存包名 + 应用名）。

### 3.5 Shizuku 激活引导

- app 内置图文引导页（简体中文）：
  1. 安装 Shizuku（给出官方渠道说明）；
  2. 开发者选项 → 无线调试 → 配对（安卓 11+ 免电脑自激活流程）；
  3. 回到本 app 授权启动。
- 主界面显示 Shizuku 连接状态徽标；未激活/断开时通知栏常驻提醒 + 主界面醒目提示，提供"重新检查"按钮。
- 运行中检测到 Shizuku binder 断开 → 服务保持存活，恢复连接后自动继续监听。

### 3.6 vivo X300 Pro 适配

- 引导页含 vivo 专属保活三件套说明：电池 → 后台耗电管理 → 允许后台高耗电；最近任务卡片下拉锁定；i管家 → 自启动允许。
- 首次安装的"未知来源"确认、OriginOS 风险提示的应对说明。

## 4. 技术方案

### 4.1 技术栈

- Kotlin + 传统 View/XML + Material Components（不用 Compose，控制体积与构建时间）；简体中文界面，跟随系统深色模式。
- minSdk 26 / targetSdk 35。
- 依赖仅：Shizuku API（`dev.rikka.shizuku:api` + `provider`）、AndroidX 基础库、Material。零第三方 SDK，无任何联网权限。

### 4.2 剪贴板监听实现（关键技术点）

- 路线：**Shizuku UserService** —— 一个以 shell 身份运行的用户进程，绕开 Android 10+ 对普通应用的后台剪贴板封锁与 hidden API 限制。
- UserService 内通过 binder 调用系统 `IClipboard`（`getPrimaryClip` / `addPrimaryClipChangedListener`）。
- **已知风险**：`IClipboard` AIDL 方法签名随 Android 版本变化（如 Android 14 增加 deviceId 参数）。**实施计划的第一步是做最小 spike**：在 X300 Pro 实机（Android 15/16）上验证 IClipboard 直调可行性；若直调不稳，备选顺序：
  1. 反射 + Parcel 手工 transact（按版本分支拼参数）；
  2. `service call clipboard` 输出解析（shell 命令，解析最脏但最不依赖签名）。
- 权限自查失败、Shizuku 未装/未激活时，服务降级为"待命"状态并提示，不崩溃、不反复重试。

### 4.3 架构

- `ClipboardPoller`（UserService 侧）：读剪贴板 + 原始文本回调。
- `JsonMatcher`：纯函数识别与指纹，便于单独验证。
- `CaptureService`（前台服务）：调度轮询、触发动作、通知。
- `ArchiveWriter`：MediaStore 存档。
- `TargetAppLauncher`：拉起目标 app。
- UI 层：MainActivity（主界面 + 引导 + 选择器三个界面）。

### 4.4 数据持久化

SharedPreferences 三项：目标 app 包名、存档开关、最近触发指纹。无数据库、无网络。

## 5. 交付与构建

- 新建独立 GitHub 公开仓库（与博客仓库分离，构建链无关）：`tianshihao2003/coc-village-listener`（名字实施时可微调）。
- GitHub Actions：push 到 main 自动 `assembleRelease`；打 tag（如 `v1.0.0`）自动创建 GitHub Release 并上传 APK。
- 签名：项目内生成一个固定 keystore 提交进仓库（自用应用，无泄密风险），保证后续版本可覆盖安装；**debug 签名质量即可，不追求 Play 上架规范**。
- 站长拿到手的永远是 Release 页里那个 APK 链接，手机浏览器直接下载安装。

## 6. 边界（v1 不做）

- 不做自动点击游戏菜单（自动提取那一整套；Shizuku 模拟点击留作 v2 能力）。
- 不做自动把 JSON 粘贴进目标 app（无障碍注入，视使用反馈再定）。
- 不做历史记录界面、多账号管理、云端同步、任何联网功能。
- 不做 iOS（系统无对应能力）。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| IClipboard 跨版本签名变化 | §4.2 spike 优先 + 两级备选；最终以 X300 Pro 实机验证为准 |
| OriginOS 杀后台 | §3.6 保活指引 + 前台服务；实测验证 |
| Shizuku 重启后失效 | app 检测并通知提醒，引导页 30 秒重激活 |
| 自签 APK 被 OriginOS 拦截 | 引导页说明"继续安装"路径 |
| 模拟器剪贴板同步与手机无关 | 本 app 仅服务手机场景，模拟器场景不受影响 |
